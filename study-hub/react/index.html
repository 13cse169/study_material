Foundations

Promises & Async / Await

React applications frequently fetch data from APIs. Understanding asynchronous JavaScript is essential.

Promises → async/await
// Promise chain
fetch("https://api.example.com/users")
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error(error));

// async / await (cleaner syntax)
async function fetchUsers() {
  try {
    const response = await fetch("https://api.example.com/users");
    const data = await response.json();
    console.log(data);
    return data;
  } catch (error) {
    console.error("Failed to fetch:", error);
  }
}

// Parallel requests
async function fetchMultiple() {
  const [users, posts] = await Promise.all([
    fetch("/api/users").then(r => r.json()),
    fetch("/api/posts").then(r => r.json())
  ]);
  return { users, posts };
}
🟡 Section 2 — React Basics
React Basics

What is React?

React is an open-source JavaScript library (not a framework) created by Facebook/Meta for building fast, interactive user interfaces using a component-based architecture.

🧩 Component-Based

UI is split into reusable, independent pieces called components. Each manages its own logic and appearance.

🔄 Reactive Updates

React automatically re-renders only the parts that changed when data (state) updates — no manual DOM manipulation needed.

⚡ Virtual DOM

React keeps a lightweight copy of the DOM in memory and calculates the minimal changes needed — making updates very fast.

🌍 Ecosystem

Massive ecosystem: React Router for navigation, Redux for state, Next.js for SSR, and thousands of community packages.

React Basics

Virtual DOM

The Virtual DOM is React's secret sauce for performance. Here's how it works:

State Changeuser action / data update
New Virtual DOMlightweight JS object tree
Diffing Algorithmcompare old vs new VDOM
Real DOM Updateonly changed nodes patched

Key insight: Instead of re-rendering the entire page, React only updates the specific DOM nodes that changed. This is called reconciliation.

React Basics

Functional Components

Components are the building blocks of React UI. A functional component is simply a JavaScript function that returns JSX.

Functional Component Example
// A simple functional component
function Welcome() {
  return (
    <div className="welcome-card">
      <h1>Welcome to React!</h1>
      <p>This is a functional component.</p>
    </div>
  );
}

// Arrow function style (common in modern React)
const Button = () => {
  return <button className="btn">Click Me</button>;
};

// Composing components
function App() {
  return (
    <div>
      <Welcome />      {/* Use like HTML tags */}
      <Button />
      <Welcome />      {/* Reuse anywhere! */}
    </div>
  );
}

export default App;

Rule: Component names must start with an uppercase letter. myComponent → React treats as HTML tag. MyComponent → React treats as a component.

React Basics

State — useState Hook

State is data that can change over time. When state changes, React automatically re-renders the component. useState is the hook to add state to functional components.

useState Counter Example
import React, { useState } from "react";

function Counter() {
  // [currentValue, setterFunction] = useState(initialValue)
  const [count, setCount] = useState(0);
  const [name, setName] = useState("Alice");

  return (
    <div>
      <h2>Count: {count}</h2>

      {/* Update state using setter */}
      <button onClick={() => setCount(count + 1)}>+1</button>
      <button onClick={() => setCount(count - 1)}>-1</button>
      <button onClick={() => setCount(0)}>Reset</button>

      {/* Functional update (safer for async) */}
      <button onClick={() => setCount(prev => prev + 5)}>+5</button>

      <p>User: {name}</p>
      <button onClick={() => setName("Bob")}>Change Name</button>
    </div>
  );
}

Event Handling

React uses camelCase event handlers and passes synthetic events — a cross-browser wrapper around native browser events.

Event Handling Examples
function EventDemo() {
  const handleClick = () => alert("Button clicked!");

  const handleSubmit = (e) => {
    e.preventDefault(); // prevent page reload
    console.log("Form submitted");
  };

  const handleChange = (e) => {
    console.log(e.target.value); // input value
  };

  const handleKeyDown = (e) => {
    if (e.key === "Enter") console.log("Enter pressed!");
  };

  return (
    <form onSubmit={handleSubmit}>
      <input
        type="text"
        onChange={handleChange}
        onKeyDown={handleKeyDown}
        placeholder="Type something..."
      />
      <button type="button" onClick={handleClick}>
        Click Me
      </button>
      {/* Inline with arrow — OK for simple cases */}
      <button onMouseEnter={() => console.log("Hovered!")}>
        Hover Me
      </button>
      <button type="submit">Submit</button>
    </form>
  );
}

Intermediate

useEffect Hook

useEffect lets you perform side effects in components: fetching data, subscriptions, DOM mutations, timers, etc.

useEffect — API Call Example
import React, { useState, useEffect } from "react";

function UserList() {
  const [users, setUsers]     = useState([]);
  const [loading, setLoading] = useState(true);

  // Runs once after mount (empty dependency array [])
  useEffect(() => {
    async function fetchUsers() {
      const res  = await fetch("https://jsonplaceholder.typicode.com/users");
      const data = await res.json();
      setUsers(data);
      setLoading(false);
    }
    fetchUsers();
  }, []); // <-- [] = run only on mount

  if (loading) return <p>Loading...</p>;

  return (
    <ul>
      {users.map(u => <li key={u.id}>{u.name}</li>)}
    </ul>
  );
}

// Dependency array variations:
// useEffect(() => {...})        — runs after EVERY render
// useEffect(() => {...}, [])    — runs ONCE after mount
// useEffect(() => {...}, [id])  — runs when `id` changes

// Cleanup (e.g., clear timers, subscriptions)
useEffect(() => {
  const timer = setInterval(() => tick(), 1000);
  return () => clearInterval(timer); // cleanup
}, []);

Conditional Rendering

Conditional Rendering Patterns
function UserStatus({ isLoggedIn, role, notifications }) {
  // 1. if/else (outside JSX)
  if (!isLoggedIn) {
    return <p>Please log in.</p>;
  }

  return (
    <div>
      {/* 2. Ternary operator */}
      <h2>{isLoggedIn ? "Welcome back!" : "Please log in"}</h2>

      {/* 3. && short-circuit (render if truthy) */}
      {notifications > 0 && (
        <span className="badge">{notifications} new</span>
      )}

      {/* 4. Switch-like with object map */}
      {{
        admin:  <AdminPanel />,
        editor: <EditorPanel />,
        user:   <UserPanel />,
      }[role]}
    </div>
  );
}

Forms — Controlled Components

A controlled component is one where React state is the single source of truth for form data.

Controlled Form
function LoginForm() {
  const [formData, setFormData] = useState({
    email: "",
    password: "",
  });

  // Generic handler for all fields
  const handleChange = (e) => {
    const { name, value } = e.target;
    setFormData(prev => ({ ...prev, [name]: value }));
  };

  const handleSubmit = (e) => {
    e.preventDefault();
    console.log("Submitted:", formData);
    // send to API, validate, etc.
  };

  return (
    <form onSubmit={handleSubmit}>
      <input
        type="email"
        name="email"
        value={formData.email}
        onChange={handleChange}
        placeholder="Email"
        required
      />
      <input
        type="password"
        name="password"
        value={formData.password}
        onChange={handleChange}
        placeholder="Password"
        required
      />
      <button type="submit">Log In</button>
    </form>
  );
}
Intermediate

Lifting State Up

When two components need to share state, lift the state to their closest common ancestor and pass it down via props.

Lifting State Pattern
// Parent holds the shared state
function TemperatureConverter() {
  const [celsius, setCelsius] = useState("");

  const toCelsius = (f) => ((f - 32) * 5) / 9;
  const toFahrenheit = (c) => (c * 9) / 5 + 32;

  return (
    <div>
      {/* Pass state + setter to both children */}
      <TempInput
        scale="Celsius"
        value={celsius}
        onChange={setCelsius}
      />
      <TempInput
        scale="Fahrenheit"
        value={celsius !== "" ? toFahrenheit(celsius) : ""}
        onChange={(f) => setCelsius(toCelsius(f))}
      />
    </div>
  );
}

// Child receives value + onChange via props
function TempInput({ scale, value, onChange }) {
  return (
    <label>
      {scale}: <input
        type="number"
        value={value}
        onChange={(e) => onChange(e.target.value)}
      />
    </label>
  );
}

Context API

Context API solves prop drilling — passing props through many levels. It provides a way to share state globally without passing props at every level.

Context API — Theme Example
import React, { createContext, useContext, useState } from "react";

// 1. Create context
const ThemeContext = createContext();

// 2. Provider — wraps the app, provides value
function ThemeProvider({ children }) {
  const [theme, setTheme] = useState("light");

  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}

// 3. Consume anywhere — no prop drilling!
function Header() {
  const { theme, setTheme } = useContext(ThemeContext);
  return (
    <header className={`header-${theme}`}>
      <h1>My App</h1>
      <button onClick={() => setTheme(t => t === "light" ? "dark" : "light")}>
        Toggle Theme
      </button>
    </header>
  );
}

// Wrap app in provider
function App() {
  return (
    <ThemeProvider>
      <Header />
      <Main />
    </ThemeProvider>
  );
}

// npm install @reduxjs/toolkit react-redux
import { createSlice, configureStore } from "@reduxjs/toolkit";
import { Provider, useSelector, useDispatch } from "react-redux";

// Slice = reducer + actions
const counterSlice = createSlice({
  name: "counter",
  initialState: { value: 0 },
  reducers: {
    increment: state => { state.value += 1; },
    decrement: state => { state.value -= 1; },
    reset:     state => { state.value  = 0; },
  },
});

// Store
const store = configureStore({ reducer: { counter: counterSlice.reducer } });

// Component
function Counter() {
  const count    = useSelector(state => state.counter.value);
  const dispatch = useDispatch();

  return (
    <div>
      <span>{count}</span>
      <button onClick={() => dispatch(counterSlice.actions.increment())}>+</button>
      <button onClick={() => dispatch(counterSlice.actions.decrement())}>-</button>
    </div>
  );
}

Performance Optimization

useMemo & useCallback
import { useMemo, useCallback, memo } from "react";

// useMemo — cache expensive computations
function ExpensiveList({ items, filter }) {
  const filteredItems = useMemo(
    () => items.filter(item => item.includes(filter)),
    [items, filter] // recalculate only when these change
  );
  return <ul>{filteredItems.map(i => <li key={i}>{i}</li>)}</ul>;
}

// useCallback — cache function references
function Parent() {
  const [count, setCount] = useState(0);

  const handleClick = useCallback(() => {
    console.log("clicked");
  }, []); // stable reference — won't cause Child re-renders

  return <Child onClick={handleClick} />;
}

// React.memo — skip re-render if props unchanged
const Child = memo(function Child({ onClick }) {
  console.log("Child rendered");
  return <button onClick={onClick}>Click</button>;
});

// React.lazy — code splitting

Custom Hooks

Custom hooks let you extract and reuse stateful logic across components. They always start with use.

useFetch & useLocalStorage Custom Hooks
// useFetch — reusable data fetching hook
function useFetch(url) {
  const [data, setData]       = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError]     = useState(null);

  useEffect(() => {
    setLoading(true);
    fetch(url)
      .then(r => r.json())
      .then(d => { setData(d);    setLoading(false); })
      .catch(e => { setError(e); setLoading(false); });
  }, [url]);

  return { data, loading, error };
}

// Use it in any component
function Posts() {
  const { data, loading, error } = useFetch("/api/posts");

  if (loading) return <p>Loading...</p>;
  if (error)   return <p>Error!</p>;
  return <ul>{data.map(p => <li key={p.id}>{p.title}</li>)}</ul>;
}

// useLocalStorage — persist state to localStorage
function useLocalStorage(key, initial) {
  const [value, setValue] = useState(
    () => JSON.parse(localStorage.getItem(key)) ?? initial
  );
  const set = (v) => {
    setValue(v);
    localStorage.setItem(key, JSON.stringify(v));
  };
  return [value, set];
}

// ── Higher-Order Component (HOC) ───────────────────
// A function that takes a component and returns a new enhanced component
function withAuth(WrappedComponent) {
  return function AuthenticatedComponent(props) {
    const isLoggedIn = !!localStorage.getItem("token");
    if (!isLoggedIn) return <Redirect to="/login" />;
    return <WrappedComponent {...props} />;
  };
}
const ProtectedDashboard = withAuth(Dashboard);

// ── Render Props ───────────────────────────────────
// Pass a function as a prop to control what gets rendered
function MouseTracker({ render }) {
  const [position, setPosition] = useState({ x: 0, y: 0 });

  return (
    <div onMouseMove={e => setPosition({ x: e.clientX, y: e.clientY })}>
      {render(position)}  {/* Call render prop with data */}
    </div>
  );
}

// Usage
<MouseTracker render={({ x, y }) => (
  <p>Mouse is at {x}, {y}</p>
)} />

🟢 Beginner

React is an open-source JavaScript library by Meta for building UIs using a component-based approach. Key advantages: Virtual DOM for performance, reusable components, massive ecosystem, declarative syntax (describe what to render, not how), and one-way data flow that makes apps predictable and easy to debug.

JSX (JavaScript XML) is a syntax extension that lets you write HTML-like code inside JavaScript. It's compiled by Babel to React.createElement() calls. Example: <h1>Hello</h1> becomes React.createElement("h1", null, "Hello"). Key rules: use className not class, all tags must close, return single root element.

🟠 Intermediate

Hooks are functions that let functional components use React features like state and lifecycle. Introduced in React 16.8. Rules: only call hooks at the top level (not inside loops/conditions), only call in React functions. Common hooks: useState (state), useEffect (side effects), useContext (context), useRef (DOM refs), useMemo/useCallback (performance).

  • useEffect(() => {...}) — runs after every render
  • useEffect(() => {...}, []) — runs once after mount (componentDidMount)
  • useEffect(() => {...}, [id]) — runs when id changes (componentDidUpdate)
  • Return cleanup function for componentWillUnmount behavior

Controlled: React state drives the form. value={state} + onChange handler. Full control, easy validation.
Uncontrolled: DOM manages the value. Access via useRef. Simpler for basic forms, harder to validate. Generally prefer controlled components in React.

🔵 Advanced

The Real DOM is slow to update because every change triggers layout recalculation. React maintains a Virtual DOM (a lightweight JS object copy). On state change: (1) React creates a new VDOM, (2) compares it with the previous VDOM using its diffing algorithm, (3) calculates the minimal set of changes needed, (4) applies only those changes to the Real DOM. This process is called reconciliation.

React 16+ uses the Fiber reconciler. Fiber is a unit of work representing a component in the tree. Key concepts: Render phase (traverses the fiber tree, determines changes — can be interrupted/resumed), Commit phase (applies changes to the DOM — synchronous, cannot be interrupted). This allows React to prioritize urgent updates (user input) over less urgent ones (data loading), enabling Concurrent Mode.

  • React.memo — skip re-render if props didn't change
  • useMemo — cache expensive computed values
  • useCallback — cache function references
  • React.lazy + Suspense — code splitting, load components lazily
  • Virtualization — render only visible list items (react-virtual, react-window)
  • Avoid anonymous functions in JSX — prevents unnecessary re-renders of children
  • Key prop — help React identify which items changed in lists
