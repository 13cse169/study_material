Variables & Data Types

JS

JavaScript has three ways to declare variables: var, let, and const. Modern JS strongly prefers let and const.

  • var — function-scoped, hoisted, avoid in modern code
  • let — block-scoped, reassignable, preferred for mutable values
  • const — block-scoped, cannot be reassigned (but object properties can mutate)
JavaScript 
// Primitive types
const name    = "Alice";         // string
const age     = 30;             // number
const active  = true;           // boolean
const nothing = null;           // null
let   undef;                    // undefined
const id      = Symbol("id");   // symbol
const big     = 9007199254740991n; // BigInt

// Reference types
const arr     = [1, 2, 3];
const obj     = { x: 10, y: 20 };
const fn      = () => "hello";

// Type checking
console.log(typeof name);   // "string"
console.log(typeof arr);    // "object"
console.log(Array.isArray(arr)); // true

Module 3
Core JavaScript
Deep concepts that separate intermediate from advanced developers.

Scope

Determines where variables are accessible. Block, function, and global scopes each have different visibility rules.

Hoisting

Variable and function declarations are moved to the top of their scope at compile time. var is initialized to undefined; let/const enter a temporal dead zone.

Closures

A function that "closes over" variables from its outer scope, retaining access even after the outer function has returned.

Prototypes

Every JS object has a prototype chain. Inheritance is prototypal — methods are looked up the chain at runtime.

Closures — Deep Dive

JS

A closure is created every time a function is defined inside another function. The inner function retains a live reference to the outer function's variables.

Use case: Data encapsulation (module pattern), factory functions, memoization, and partial application.
JavaScript
// Counter factory — classic closure example
function makeCounter(start = 0) {
  let count = start; // private variable
  return {
    increment: () => ++count,
    decrement: () => --count,
    value:     () => count,
    reset:     () => { count = start; }
  };
}

const c = makeCounter(10);
c.increment(); // 11
c.increment(); // 12
c.decrement(); // 11
console.log(c.value()); // 11

// Memoization with closure
function memoize(fn) {
  const cache = new Map();
  return (...args) => {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);
    const result = fn(...args);
    cache.set(key, result);
    return result;
  };
}

Callbacks → Promises → Async/Await

JS
Callbacks can lead to "Callback Hell" — deeply nested code that's hard to read and debug.
JavaScript
// Simple callback pattern
function fetchUser(id, callback) {
  setTimeout(() => {
    const user = { id, name: "Alice" };
    callback(null, user); // (error, data)
  }, 1000);
}

fetchUser(1, (err, user) => {
  if (err) { console.error(err); return; }
  console.log(user);
});
JavaScript
function fetchUser(id) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (id > 0) resolve({ id, name: "Alice" });
      else reject(new Error("Invalid ID"));
    }, 1000);
  });
}

fetchUser(1)
  .then(user  => console.log(user))
  .catch(err  => console.error(err))
  .finally(() => console.log("Done"));

// Parallel with Promise.all
const [u1, u2] = await Promise.all([
  fetchUser(1), fetchUser(2)
]);
JavaScript

Example: Todo App UI Logic

JS
JavaScript
class TodoApp {
  constructor() {
    this.todos = JSON.parse(localStorage.getItem("todos")) || [];
    this.input = document.querySelector("#todo-input");
    this.list  = document.querySelector("#todo-list");
    this.init();
  }

  init() {
    document.querySelector("#add-btn")
      .addEventListener("click", () => this.add());
    this.render();
  }

  add() {
    const text = this.input.value.trim();
    if (!text) return;
    this.todos.push({ id: Date.now(), text, done: false });
    this.save();
    this.render();
    this.input.value = "";
  }

  toggle(id) {
    this.todos = this.todos.map(t =>
      t.id === id ? { ...t, done: !t.done } : t
    );
    this.save();
    this.render();
  }

  save() {
    localStorage.setItem("todos", JSON.stringify(this.todos));
  }

  render() {
    this.list.innerHTML = this.todos
      .map(({ id, text, done }) => `
        <li class="${done ? 'done' : ''}">
          <span onclick="app.toggle(${id})">${text}</span>
        </li>`)
      .join("");
  }
}
const app = new TodoApp();

Execution Context & Call Stack

Advanced

Every time JavaScript executes code, it creates an Execution Context with: a Variable Environment, a Scope Chain, and a this binding. The Global Execution Context is always at the bottom of the Call Stack.

Two phases: Creation Phase (memory allocation, hoisting) → Execution Phase (code runs line by line).
JavaScript
// Debounce — delay execution until user stops
function debounce(fn, delay = 300) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}

// Throttle — limit to once per interval
function throttle(fn, limit = 300) {
  let lastCall = 0;
  return (...args) => {
    const now = Date.now();
    if (now - lastCall >= limit) {
      lastCall = now;
      return fn(...args);
    }
  };
}

const safe = val ?? "Unknown";           // nullish coalescing

Utility Types & Conditional Types

Advanced
TypeScript
interface User { id: number; name: string; email: string; age: number; }

// Built-in utility types
type PartialUser  = Partial<User>;     // all props optional
type RequiredUser = Required<User>;    // all props required

// Conditional types
type IsArray<T> = T extends any[] ? true : false;
type A = IsArray<string[]>; // true
type B = IsArray<string>;   // false

// Mapped types
type Nullable<T> = { [K in keyof T]: T[K] | null };
type NullableUser = Nullable<User>;

// Type narrowing
function processId(id: string | number) {
  if (typeof id === "string") {
    return id.toUpperCase(); // narrowed to string
  }
  return id.toFixed(2); // narrowed to number
}

V8 Engine

Google's JS engine: parses → AST → Ignition bytecode → TurboFan JIT compilation → optimized machine code.

Memory Management

JS uses automatic garbage collection (mark-and-sweep). Avoid memory leaks: clear timers, remove listeners, avoid accidental globals.

Design Patterns

JavaScript — Performance
// Virtual scrolling (render only visible items)
function getVisibleItems(items, scrollTop, viewportHeight, itemHeight) {
  const start = Math.floor(scrollTop / itemHeight);
  const end   = Math.ceil((scrollTop + viewportHeight) / itemHeight);
  return items.slice(start, end + 1);
}
