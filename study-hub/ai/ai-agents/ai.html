01 — Foundations

Prerequisite Knowledge

Before diving into AI Agents, let's solidify the core concepts that make them possible.

Artificial Intelligence

AI is the simulation of human intelligence in machines — enabling them to think, learn, reason, and solve problems. It's the broad field that encompasses everything from search algorithms to neural networks.

The Big Picture

Machine Learning

A subset of AI where systems learn patterns from data without being explicitly programmed. ML models improve through experience — like a spam filter that gets smarter as it sees more emails.

Data-Driven

Deep Learning

A subset of ML using layered neural networks (inspired by the brain) to handle unstructured data like images, audio, and text. Powers face recognition, voice assistants, and image generation.

Neural Networks

Generative AI

AI that creates new content — text, images, code, music. Models like GPT-4 and Gemini are trained on massive datasets and can generate human-quality output, enabling the AI Agent revolution.

Creative AI

Why Do We Need AI Agents?

Traditional AI models are passive — you give input, they give output. But real-world problems require autonomous decision-making, multi-step reasoning, and interaction with the environment. AI Agents bridge this gap by acting, not just reacting. They can browse the web, run code, call APIs, and complete tasks end-to-end without human intervention at every step.

02 — Introduction

What Is an AI Agent?

"

An AI Agent is an autonomous software entity that perceives its environment through sensors, processes that information, and takes actions to achieve specific goals — optionally learning and improving over time.

Key Characteristics

01

Autonomy

Operates independently without constant human intervention. Makes its own decisions based on its goals and environment state.

02

Perception

Receives information from its environment via sensors — cameras, microphones, API data, text input, or sensor readings.

03

Decision-Making

Analyzes perceived data and selects the best action using rules, search algorithms, learned models, or LLM reasoning.

04

Action

Executes decisions via actuators — sending messages, calling APIs, moving robots, clicking UI elements, or generating output.

Real-World Examples

Chatbots (e.g., ChatGPT)

Perceive text input → process with LLM → generate and send a response. Can chain tool calls for multi-step tasks.

Recommendation Systems (e.g., Netflix)

Perceive viewing history → decide what to show → present recommendations → learn from clicks.

Virtual Assistants (e.g., Siri, Alexa)

Perceive voice → transcribe → understand intent → take action (play music, set alarm, answer questions).

03 — Components

Components of an AI Agent

Every AI agent — from a simple chatbot to a complex autonomous robot — is built from these four core components.

Environment

The context in which the agent operates. Can be physical (factory floor), digital (web browser), or virtual (game world). The environment provides stimuli and receives the agent's actions.

Example: For a self-driving car agent, the environment is the road — with lanes, traffic lights, other vehicles, and pedestrians.

Sensors (Input)

The mechanisms through which an agent perceives its environment. Sensors translate real-world signals into data the agent can process.

Examples: Camera (vision), microphone (sound), keyboard (text), REST API responses (data), GPS (location).

Actuators (Output)

The mechanisms through which an agent affects its environment. After deciding what to do, actuators carry out the action.

Examples: Robot motor (move), speaker (speak), HTTP request (call API), display (show text), database write (store).

Decision Logic / Brain

The core intelligence of the agent — takes sensor input, applies reasoning (rules, ML, LLM), and selects the best action to take.

Examples: if-else rules, neural network, GPT-4 API call, Q-learning policy, decision tree.
04 — Types

Types of AI Agents

Type 01

Simple Reflex Agent

Acts solely on current percept, ignoring history. Uses condition-action rules: "IF this THEN that." No memory, no planning.

Example: A thermostat — if temp < 68°F, turn heater on.
Use when: Environment is simple, fully observable, and rules cover all cases.
Type 02

Model-Based Reflex Agent

Maintains an internal model (memory) of the world — tracks unobservable state to make better decisions even with partial information.

Example: A vacuum robot that remembers which rooms it has already cleaned.
Use when: Environment is partially observable and history matters for current decisions.
Type 03

Goal-Based Agent

Has explicit goals and searches for action sequences that achieve them. Plans ahead and evaluates future states.

Example: A GPS navigation agent that finds the fastest route to your destination.
Use when: Multiple paths exist to a goal, and the agent must choose between them.
Type 04

Utility-Based Agent

Extends goal-based with a utility function to measure how desirable each outcome is. Chooses actions that maximise utility (quality of solution).

Example: A stock-trading agent that weighs risk vs return to pick the best trade.
Use when: There are conflicting goals or trade-offs (speed vs safety, cost vs quality).
Type 05

Learning Agent

Improves its performance over time through experience. Has four components: Learning Element, Performance Element, Critic, and Problem Generator.

Example: AlphaGo — learned to play Go at superhuman level through self-play reinforcement learning.
Use when: Optimal behaviour is unknown upfront and must be discovered through interaction.

Common Architecture Patterns

Reactive Architecture

Direct stimulus-response mapping. No world model. Extremely fast but limited to simple tasks.

Deliberative Architecture

Maintains world model, plans ahead using search. Slower but can handle complex, multi-step problems.

Hybrid Architecture

Combines reactive (fast, low-level) with deliberative (slow, high-level) layers. Used in modern robots and AI systems.

06 — How It Works

Step-by-Step Agent Flow

01

Receive Input

The agent receives raw data from its environment — a user message, a sensor reading, an API response, or any external stimulus.

e.g., User types: "Book me a flight to Paris next Friday"
02

Analyse Environment

Processes the input — parses text, identifies intent, checks context memory, and builds an understanding of the current state.

Intent: book_flight | Destination: Paris | Date: next Friday
03

Decide Action

Applies reasoning — consults rules, learned policies, or LLM reasoning — to select the best next action or sequence of actions.

Decision: Call flight_search(origin=current, dest=Paris, date=2025-06-06)
04

Execute Action

Carries out the chosen action via actuators — calls an API, sends a command, generates a response, or triggers a physical motor.

API call → returns 3 flights → presents options to user
05

Learn (Optional)

Updates its model, policy, or memory based on feedback — did the action achieve the goal? What reward was received? Adjusts future behaviour accordingly.

User selects flight → store preference → improve future recommendations
07 — Decision-Making

How Agents Make Decisions

Rule-Based Logic

Explicit IF-THEN rules written by humans. Fast, explainable, but brittle — breaks down when encountering situations not covered by the rules.

Fast & transparent Doesn't scale

Search-Based Decisions

Explores a tree of possible futures (BFS, DFS, A* search) to find a path that leads to the goal. Used in games and planning problems.

Finds optimal paths Computationally expensive

Learning-Based Decisions

Trains a model on data to learn decision boundaries. The agent's "brain" is a learned function — neural networks, SVMs, decision trees.

Handles complexity Needs lots of data

Reinforcement Learning

Agent learns by trial-and-error. Receives rewards for good actions, penalties for bad ones. Over time, learns the optimal policy through experience.

Agent → action → Environment → reward + state → Agent
Learns optimal policy Slow to train

Simple Rule-Based Agent
# Simple Rule-Based AI Agent
# Demonstrates the most basic form of an AI agent

class SimpleReflexAgent:
    """A thermostat-style agent using condition-action rules."""

    def __init__(self, target_temp=72):
        self.target_temp = target_temp
        self.state = "idle"

    def perceive(self, current_temp):
        """Sensor: read environment."""
        return {"temperature": current_temp}

    def decide(self, percept):
        """Decision logic: condition → action rules."""
        temp = percept["temperature"]

        if temp < self.target_temp - 2:
            return "heat_on"
        elif temp > self.target_temp + 2:
            return "cool_on"
        else:
            return "idle"

    def act(self, action):
        """Actuator: execute the decision."""
        self.state = action
        actions = {
            "heat_on": "🔥 Heater ON",
            "cool_on": "❄️  AC ON",
            "idle":    "✅ System IDLE"
        }
        print(actions[action])

    def run(self, current_temp):
        """Full agent loop: perceive → decide → act."""
        percept = self.perceive(current_temp)
        action  = self.decide(percept)
        self.act(action)

# Usage
agent = SimpleReflexAgent(target_temp=72)
agent.run(65)  # → 🔥 Heater ON
agent.run(72)  # → ✅ System IDLE
agent.run(80)  # → ❄️  AC ON
Chatbot Agent Logic
# Simple Chatbot Agent with intent detection

import re

class ChatbotAgent:
    def __init__(self):
        self.memory = []  # conversation history
        self.intents = {
            "greeting": ["hello", "hi", "hey"],
            "farewell": ["bye", "goodbye", "exit"],
            "weather":  ["weather", "temperature", "rain"],
            "help":     ["help", "assist", "support"],
        }
        self.responses = {
            "greeting": "Hello! How can I help you today?",
            "farewell": "Goodbye! Have a great day!",
            "weather":  "I'll check the weather for you...",
            "help":     "Sure! Tell me what you need help with.",
            "default":  "I didn't quite understand that. Can you rephrase?"
        }

    def perceive(self, user_input):
        """Clean and tokenize input."""
        return user_input.lower().strip()

    def detect_intent(self, text):
        """Match text against known intent keywords."""
        for intent, keywords in self.intents.items():
            if any(kw in text for kw in keywords):
                return intent
        return "default"

    def decide(self, text):
        """Choose response based on detected intent."""
        intent = self.detect_intent(text)
        return self.responses[intent]

    def act(self, response):
        """Output the response (actuator)."""
        print(f"Bot: {response}")
        self.memory.append(response)

    def chat(self, user_input):
        """Full agent loop."""
        text     = self.perceive(user_input)
        response = self.decide(text)
        self.act(response)

# Usage
bot = ChatbotAgent()
bot.chat("Hello there!")   # → Hello! How can I help you today?
bot.chat("What's the weather?") # → I'll check the weather for you...
Agent Loop — Pseudo-code
# Universal Agent Loop — the heartbeat of any agent

def agent_loop(agent, environment, max_steps=100):
    """
    Core agent control loop.
    Every AI agent — from thermostat to GPT — follows this pattern.
    """
    percept = environment.initial_state()

    for step in range(max_steps):
        # 1. PERCEIVE — sense the environment
        observation = agent.perceive(percept)

        # 2. DECIDE — choose an action
        action = agent.decide(observation)

        # 3. ACT — execute the action
        result = environment.apply(action)

        # 4. LEARN — update from feedback (optional)
        if hasattr(agent, 'learn'):
            reward = environment.get_reward()
            agent.learn(observation, action, reward)

        # 5. UPDATE — get new state for next iteration
        percept = result

        # 6. CHECK — are we done?
        if environment.is_terminal():
            print(f"✅ Goal reached at step {step}")
            break

    return agent.get_performance()

# Key insight: the loop is always the same.
# What changes is WHAT'S INSIDE perceive(), decide(), and act().
Basic Decision-Making Function
# Utility-Based Decision Function
# Agent scores each possible action and picks the best

def utility_decision(state, possible_actions, utility_fn):
    """
    Choose the action with highest expected utility.

    Args:
        state:            Current world state
        possible_actions: List of available actions
        utility_fn:       Function(state, action) → score (float)

    Returns:
        Best action to take
    """
    scores = {
        action: utility_fn(state, action)
        for action in possible_actions
    }

    # Pick action with highest utility score
    best_action = max(scores, key=lambda a: scores[a])

    print(f"Scores: {scores}")
    print(f"Chosen: {best_action} ({scores[best_action]:.2f})")
    return best_action

# Example: route-planning agent
def route_utility(state, action):
    scores = {
        "highway":  0.85,  # fast but tolls
        "city_road": 0.60, # slow but scenic
        "shortcut": 0.75,  # medium, less certain
    }
    return scores.get(action, 0.0)

result = utility_decision(
    state={"traffic": "low"},
    possible_actions=["highway", "city_road", "shortcut"],
    utility_fn=route_utility
)
# Output: Chosen: highway (0.85)

10 — Challenges

Challenges & Limitations

Limited Intelligence

Simple agents can only handle situations covered by their rules or training data. They fail at edge cases and novel scenarios outside their training distribution.

Data Dependency

ML-based agents require massive, clean, well-labelled datasets. Bias in training data leads to biased agent behaviour — a critical ethical issue.

Scalability Issues

Complex agents are computationally expensive. Real-time decision-making at scale requires significant infrastructure, latency management, and cost.

Real-World Uncertainty

The real world is noisy, unpredictable, and partially observable. Agents trained in simulation often fail when deployed in real environments (the "sim-to-real gap").

Safety & Alignment

Ensuring agents pursue the goals humans intended — not unintended proxies — is an open research problem. Misaligned agents can cause serious harm.

Explainability

Deep learning agents are "black boxes." Understanding why an agent made a specific decision is crucial for high-stakes domains like healthcare and finance.

12 — Interview Prep

Interview Questions & Answers

Beginner

An AI agent is an autonomous software entity that perceives its environment through sensors, processes that information using decision logic, and takes actions via actuators to achieve specific goals — all without requiring constant human input.

Key analogy: Think of a chess AI — it observes the board (perception), calculates the best move (decision), and moves a piece (action). It does this autonomously, without someone telling it what to do each turn.

The four core components of any AI agent are:

  • Environment — The world the agent operates in (physical, digital, or simulated)
  • Sensors — Input mechanisms (camera, microphone, text input, APIs)
  • Decision Logic — The brain: rules, ML models, or LLMs that choose actions
  • Actuators — Output mechanisms (motors, API calls, text responses, database writes)

AI is the broad field/concept — any system that simulates intelligence. An AI Agent is a specific implementation: an autonomous entity that perceives, decides, and acts in a loop.

Not all AI is agentic. A model that answers a single question (like a search engine) is AI, but not an agent. An agent that searches the web, reads results, writes a report, and emails it — autonomously — is an AI agent.

Intermediate
  1. Simple Reflex — IF-THEN rules, no memory (e.g., thermostat)
  2. Model-Based — Maintains internal world model (e.g., vacuum robot with map)
  3. Goal-Based — Plans ahead to reach a goal (e.g., GPS navigation)
  4. Utility-Based — Maximises a utility function, handles trade-offs (e.g., stock trader)
  5. Learning Agent — Improves through experience/feedback (e.g., AlphaGo)

Each type builds on the previous — a learning agent can incorporate all the other approaches.

AI agents use three main decision-making approaches:

  • Rule-Based: Explicit IF condition THEN action rules. Fast and explainable but doesn't scale.
  • Search-Based: Explores a tree of possible future states (A*, BFS, MCTS). Good for planning in well-defined problems.
  • Learning-Based: A trained model predicts the best action. Used in complex, high-dimensional environments.

The PDA loop is the fundamental operating cycle of every AI agent:

  1. Perceive: Agent reads input from environment via sensors
  2. Decide: Agent processes input and selects an action
  3. Act: Agent executes the action, affecting the environment
  4. Loop repeats — the new environment state becomes the next perception

This loop runs continuously — thousands of times per second in a game agent, or once per user message in a chatbot.

Advanced

A learning agent has four internal components:

  • Performance Element: Makes decisions (the current policy/model)
  • Critic: Evaluates performance — provides feedback/reward signal
  • Learning Element: Updates the performance element based on critic feedback
  • Problem Generator: Suggests exploratory actions to discover new knowledge

Example: AlphaGo's performance element plays moves, the critic scores positions, the learning element updates the neural network via self-play, and the problem generator explores novel game positions.

Goal-Based Agent: Binary success — either achieves the goal or doesn't. Example: reaching a destination. Multiple paths may satisfy the goal equally.

Utility-Based Agent: Measures HOW WELL goals are achieved with a continuous utility score. Example: reaching a destination quickly, cheaply, and safely — all three matter and must be balanced.

Key difference: When there are conflicting goals or the quality of the solution matters (not just whether you reached it), you need a utility-based agent.

A Multi-Agent System is an environment with multiple interacting AI agents. Each agent is autonomous but must coordinate, compete, or communicate with others.

Key properties:

  • Cooperation: Agents work together (e.g., warehouse robot swarm)
  • Competition: Agents compete (e.g., agents in a market simulation)
  • Emergent behaviour: Complex system behaviour arises from simple agent interactions

Examples: AutoGen (Microsoft), CrewAI, MetaGPT — frameworks where multiple LLM agents collaborate on complex tasks.

RL is the primary learning paradigm for training agents in interactive environments:

  • Agent takes actions in an environment
  • Environment returns reward + new state
  • Agent learns a policy π(state) → action that maximises cumulative reward

Key algorithms: Q-Learning, Deep Q-Network (DQN), Proximal Policy Optimization (PPO), Actor-Critic methods.

Used in: Game agents (AlphaGo, Atari), robotics locomotion, dialogue systems, and RLHF (training ChatGPT to be helpful).
